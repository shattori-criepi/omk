# ESP32-C3＋SEN66一体型PCB Rev.A 計画中止と研究用PCBへのAI活用記録

- **決定日:** 2026-08-04
- **ステータス:** **CANCELLED**
- **対象:** ESP32-C3、USB-C、電源、無線アンテナ、SEN66接続を一体化するRev.A

## 決定と資産の扱い

この計画は中止した。専用基板の目的はSEN66をESP32系デバイスへ接続し、Wi-Fi/MQTTで送信することだったが、USB、電源、書込み、ESD、アンテナ、差動配線および実機検証を同時に扱う必要があり、研究用の単発ノードとしては範囲が大きすぎた。

中止PCBのKiCad project、回路図、PCB、部品・footprint監査、配置補助script、PDF、中間生成物はリポジトリから削除した。これらは製造に使用できる完成設計ではなく、個別の座標や配置試行を長期保存しても再利用価値が低いためである。将来の構成は未決定とし、既製ESP32系デバイスを利用するか、必要なら小さな接続変換基板に範囲を限定する。

## AI と KiCad で有効だったこと

- 要件を回路ブロックへ分解し、信号・電源・コネクタの接続表を作ること。
- データシートの確認観点、部品候補、BOMの比較項目、確認待ち事項を整理すること。
- KiCad APIやスクリプトで、定型的な回路図要素の生成、部品属性の入力、配置のたたき台を作ること。
- ERC、PDF出力、差分確認などの反復手順を自動化し、未確認事項を文書化すること。

AI生成物は、検討の初速と記録の一貫性を上げる補助として有効だった。特に、設計意図と確認事項を文章・表に残しながら作業する用途では効果が大きい。

## 自動化だけでは割り切れなかったこと

- ライブラリ形式やKiCad APIの互換性を吸収する作業は、手作業より不安定になることがある。
- footprintの実装向き、基板外形、コネクタの嵌合、ケーブル曲げ、アンテナkeepout、放熱、組立性は、座標を生成しても解決しない。
- データシートの版、推奨land pattern、部品調達可否、実装機条件はAIの推測で確定してはならない。

研究用の少数試作では、AIで回路図の下書き・確認表・生成補助を作り、複雑な配置自動化は最小限に留めるのが現実的である。既製の開発ボードへ任せられるUSB、電源、書込み、無線を再実装しないことも、有効な範囲制御である。

## 最低限の人間確認

AIが生成・編集したKiCadファイルは、実機が正常動作する証拠ではない。少なくとも次は人間が確認する。

- データシート原本と、pin番号・電圧範囲・極性・定格の照合
- footprint、向き、keepout、基板外形、コネクタ嵌合、配線・組立の目視確認
- ERC/DRCの結果を読むことと、未解決警告の扱いを決めること
- USB、電源、書込み、センサ、無線を段階的に実機確認すること

## 次回の開始条件とSTOP条件

開始前に、既製品・開発ボード・変換基板で目的を満たせない理由、必要な試作台数、評価できる人と時間を明確にする。回路図の自動生成やERC成功だけを継続根拠にしない。

次のいずれかになった時点で、設計を縮小または停止する。

- USB、電源、無線、センサ接続を同時に新規設計する必要がある。
- footprint/機構/調達の重要な確認が、実機評価へ進む前に解消できない。
- 個別の配置・生成scriptの保守量が、手動確認や既製ボード利用のコストを上回る。
- センサ計測・MQTT送信という研究目的に対し、専用PCBが新しい検証対象を増やすだけになる。
