# OMKの限定共有と将来のOSS公開方針

- **決定日:** 2026-08-20
- **ステータス:** 検討中
- **対象:** OMK repositoryの共有、OSS license、一般公開に必要な確認

## 現在の共有段階

当面は、知人の大学教員等への限定共有・試用を想定する。一般公開は将来の事項であり、
現時点で所内承認済みまたは公開決定済みであることを意味しない。再配布そのものを禁止する
方針ではないが、OMKの利用、改変、再配布について研究所が個別の責任、サポート、保守または
動作保証を負うことは意図しない。

## 将来公開時の利用者参加・運営原則

一般公開時のOMK利用者は、商用製品の顧客ではなく、自ら構築、運用し、必要に応じて改良できる
利用者・参加者として位置づける。利用、改変、fork、再配布の自由を重視する一方、maintainerは
個別の機能追加、機器対応、サポートを実装する義務を負わない。

活用例、アイデア、改善案など、OMK全体に有用な情報の共有は歓迎する。ただし、個別の利用方法に
関する質問への回答やサポートは約束しない。特定利用者固有の機能は、利用者自身のforkで開発・
維持することを基本とする。OMK全体への有用性が高い提案は、研究目的、汎用性、保守性、開発優先度
等を踏まえ、maintainer側で採用・実装する場合がある。ただし、提案を受けたことやアイデアが有用で
あることは、実装、PR review、mergeを約束するものではない。必要ならmaintainer側で実装する場合も
あり、提案者へPR作成を求めるとは限らない。

Issueは、再現可能な不具合および具体的に対応することにした課題の管理に用い、単なる機能追加
要望の受付窓口とはしない。一般的なアイデア、活用例、利用方法に関する情報共有には、まず別の場を
設ける。第一候補はGitHub Discussionsであるが、無償サポート窓口として位置づけるものではなく、
現時点でGitHub設定を変更するものでもない。コード変更を提案する場合は、目的、背景、想定用途、
OMK全体への有用性を事前に共有し、maintainerが本体への取り込みを検討する価値があると判断した
場合に、必要に応じてIssue化またはPR提出を案内する。PRは常時募集する入口ではなく、事前相談の
ないPRについてreview、merge、対応は約束しない。

電中研等が主体となる研究・実証・被験者実験でOMKを設置する場合は、一般OSS利用とは別扱いと
する。研究計画に基づき、研究実施者側が必要な設置、運用、保守、トラブル対応等を行う場合がある。
一般利用者向けの自己責任・一般サポート方針は、実験協力者へ保守責任を転嫁する意味ではない。

## OSS licenseの第一候補

一般公開時の第一候補は **GPL-3.0-or-later** とする。ただし最終決定は、以下の所内確認を
終えてから行う。

- 利用、改変、商用利用、再配布を広く認め、個別許諾を不要にする。
- 派生物を第三者へ配布する場合も、受領者のソース利用・改変の自由を維持する。
- 商用利用を禁止することが目的ではない。
- 研究成果の囲い込みを抑え、住宅内IoT・エネルギー計測における外部の改良、アイデア、
  応用事例を促進する。
- 研究成果の社会実装・社会貢献を重視し、外部コミュニティの知見を新たな研究テーマや
  社会実装へつなげる。

OMKは市販機器、公開規格、OSS、一般的な技術を組み合わせる研究用基盤であり、ソース秘匿
そのものによる競争優位は限定的と考える。一方、公開により利用者、対応機器、応用事例、
改善案が増える研究上の便益は大きい。

## 公開前の所内確認

- 著作権・職務著作の帰属、および共同研究、委託、学生、外部協力者等の権利
- STL、docsを含む全成果物の権利帰属と、第三者コード・外部素材の混入有無
- GPL-3.0-or-laterとの依存license互換性
- 特許化すべき成果の有無、およびGPLv3のpatent grantを研究所として許容できるか
- 研究所名、ロゴ、商標等の扱い、免責・無保証表現、公開範囲
- 所内の知財・法務・広報等による承認プロセス

これは法的助言ではなく、公開前に確認すべき論点の記録である。

## 技術license監査の現在地

直接依存からGPL-3.0-or-laterと明確に衝突するlicenseは、現時点では未検出である。
ただし、Python推移依存、binary配布時のSBOM、ESP-IDFのthird-party componentsは
release時に追加確認する。STL等の権利帰属は人間による確認が必要である。

root `LICENSE` はまだ追加しない。

## 将来の一般公開時

所内承認の完了後に、少なくとも次を行う。

1. root `LICENSE` を追加し、READMEのlicense sectionを更新する。
2. 必要に応じて `THIRD_PARTY_NOTICES` とSBOMを用意する。
3. Docker imageやfirmware binaryなど、release artifact単位でlicenseを確認する。
4. 承認済みの公開範囲でpublic化する。
